Graphics Algorithm Visualizer
Project Report

1. Installed Packages & Dependencies

The project relies on a few key components to function on Windows:

  • GCC Compiler (MinGW-w64): This is the C/C++ compiler suite (g++) used to translate your code into a runnable executable.
  • WinBGIm Library (64-bit port): A Windows port of the classic Borland Graphics Interface (BGI). Standard C does not have built-in graphics, so this library is used to create a window, draw lines, rectangles, colors, and handle keyboard input.
  • Windows API Libraries (gdi32, comdlg32, uuid, oleaut32, ole32): These are low-level Microsoft Windows libraries that WinBGIm depends on to draw graphics on your screen and interface with the operating system.

2. Overview of the C Program (main.c)

The C program is an Educational Algorithm Visualizer. It provides a menu-driven, graphical interface to visually demonstrate how fundamental computer graphics algorithms work step-by-step. It draws a mathematical coordinate system, plots points representing pixels, and animates the drawing process with varying speeds.

3. What Does Which File Do?

  • main.c: The core of the application. It contains the menu UI, screen drawing logic, and the mathematical implementation of all the line-drawing and clipping algorithms.
  • build.ps1: A PowerShell build script. It automates the process of compiling the graphics source code into a library, and then links that library with main.c to generate the final executable.
  • libbgi.a: A compiled static library file that contains the actual implementation of the WinBGIm graphics functions.
  • graphics.h & winbgim.h: Header files that define the available graphics functions (like line(), putpixel(), initwindow()) so that main.c can use them.
  • WinBGIm-64-main/: A folder containing the raw C++ source code used to build the libbgi.a library.
  • visualizer.exe: The final, ready-to-run Windows application that is produced after running the build script.

4. Algorithms Built & How They Work

The program builds and visualizes four core graphics algorithms:

A. DDA (Digital Differential Analyzer) Line Algorithm

  • How it works: It calculates the difference in X (dx) and Y (dy) coordinates between two points. It determines the number of "steps" required based on whichever difference is larger. It then calculates a small floating-point increment for X and Y, adding it repeatedly in a loop to draw the line.
  • Characteristics: Simple to understand, but slightly slower for a computer to execute because it relies on floating-point decimal math.

B. Bresenham's Line Algorithm

  • How it works: Highly optimized for performance. It uses only integer arithmetic (addition and subtraction). It tracks a "decision parameter" (an error value) that accumulates as the line progresses across the major axis. If the error gets too high, it increments the coordinate on the minor axis and resets the error.
  • Characteristics: Fast and precise, heavily used in hardware rendering.

C. Midpoint Line Algorithm

  • How it works: Similar to Bresenham, it's an integer-based algorithm. At each step, it calculates the exact geometric midpoint between two possible candidate pixels for the next dot. By evaluating the line's implicit equation at this midpoint, it mathematically decides which pixel is closer to the true line.

D. Cohen-Sutherland Line Clipping Algorithm

  • How it works: Used to cut off parts of a line that fall outside a designated viewing window. It divides the 2D space into 9 regions using 4-bit binary codes (Top, Bottom, Right, Left).
  • Process: It assigns a code to the start and end points of a line. By performing quick Bitwise AND/OR operations on these codes, it can "trivially accept" lines fully inside the window or "trivially reject" lines fully outside. For lines that cross the boundary, it mathematically calculates the exact intersection points to clip them perfectly.
